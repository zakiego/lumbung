# Design

Design calls for Lumbung.

## Decisions

- 2026-11-14, dashboard main screen (database overview). Variants: 1 Ledger (numbers first: KPI row, request chart, branch table), 2 Connect first (the connect snippet leads, stats come second), 3 Branch map (the branch tree is the hero, numbers and connect follow). Kept: 3, Branch map. Zaki's pick, no reason given.
- 2026-11-14, landing hero. Variants: 1 Product stage (a framed mock of the dashboard comparing a branch with main), 2 Terminal (a CLI session that creates a branch, changes it and queries it), 3 Agent chat (an AI agent working on a branch over MCP). Kept: 2, Terminal. Zaki's pick, no reason given.
- 2026-11-15, landing hero, redone without the terminal ("dont use terminal focus on svg graph animation"). Variants: 1 Timeline (branches fork off a main line), 2 Map (callers reach one server in the middle), 3 Layers (a branch lifts off the database as a second sheet), 4 Granary (data fills the rice barn the name comes from), 5 Orbit (branches and files circle main), 6 Dots (every dot of main flies across to build a copy), 7 Wave (a chart line that fans into branches), 8 Split (one round database divides in two, the new half turns green and goes away). Kept: 5, Orbit. Zaki first picked 8 (Split), saw it built, then switched ("Use orbit"), no reason given. Main is drawn solid like in the feature graphs, and the orbit lines are dotted. This replaces the 2026-11-14 Terminal pick. The hero copy is also shorter ("simplify the title, subtitle, and animation text") and the graph carries no technical detail ("focus on animation, not explain"). Orbit has no labels at all: icons say which moon is a branch and which is the bucket, because a label under a moving moon ran into its neighbors.
